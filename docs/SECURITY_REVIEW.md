## Hipótesis acotada: fragmento y Clerk

El layout global contiene Clerk y el retiro del fragmento ocurre en `requestAnimationFrame` después de `useEffect`; por tanto, no hay una barrera que garantice retirarlo antes de cualquier JavaScript. La ruta usa fragmento y `no-referrer`, y lo elimina antes de almacenar/validar/consultar dentro del procedimiento de restauración.

Se siguieron el adaptador App Router de `@clerk/nextjs@7.9.17`, el cargador de `@clerk/react@6.17.8` y telemetría/carga de scripts de `@clerk/shared@4.40.0`. El evento RouterTelemetry inspeccionado transporta router/versión; el cargador no incorpora la URL de la página. Las lecturas locales de `location.href` para resolver opciones no prueban transmisión externa.

La implementación efectiva de `globalThis.Clerk.load` procede de un script remoto ausente del árbol instalado. **No se estableció un camino concreto que transmita el fragmento a un tercero, ni se afirma una garantía absoluta del SDK remoto.** Conforme al alcance de la coordinación, esta inspección acotada cierra la pregunta de18; no exige auditar íntegro el CDN ni refactorizar el proveedor por hipótesis. No se crearon ni utilizaron capacidades reales para investigarla.
